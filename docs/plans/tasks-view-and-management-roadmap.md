# Roadmap: просмотр и управление задачами (web + JVM)

Дата: 2026-11-23. Цель: выпустить работающую платформу для web и JVM до Нового года (2026-12-31).

## Принятые ограничения

- Первый эпик (#105) реализует только просмотр: список и детали задачи.
- Второй эпик (#125) реализует управление: действия, параметры и создание задачи.
- В каждом эпике есть работа и для web, и для JVM.
- Платформенные лейблы: `web` — для web-задач; `macos` и `windows` — для JVM-задач (единого лейбла `jvm` в репозитории нет).
- Ёмкость спринтов сознательно поднята: 36–45 SP за итерацию вместо исторических 12–16 SP/неделю. Это принятый риск сжатия сроков.
- Оценки пересмотрены по фактическому состоянию кода (см. раздел «Опровергнутые допущения»).

## Опровергнутые допущения старых задач

- #127: JVM-клиент уже реализован; задача переформулирована в унификацию конфигурации.
- #128: модуль авторизации уже имеет jvm-таргет; не реализовано хранилище, плюс DI на JVM ссылается на закомментированный MAX-модуль.
- #129: `FullAppDefinition` не существует; `main.kt` jvmApp показывает только «Welcome» и не запускает навигацию.
- #132: `commonTest` в фиче задач отсутствует; тестовую инфраструктуру нужно создать.
- #130 закрыт: роль «Разработчик» нарушала правила бизнес-историй, задачи растворены в #131/#132 и эпике #125.
